# DeepSeek Harness

DeepSeek Harness (`dsh`) is the runtime the agentic layer executes on: a plugin-first
agent harness from DeepSeek AI, MIT-licensed and a `0.2` developer preview. azoth supplies
the launcher, the engineering persona, the welcome UI, the skills, the calculation tools
and the HAZOP team's role definitions. Everything DSH-specific is generated by
`tools/launch_dsh.py`, so a version bump is one edit rather than a hunt through YAML.

## The launcher

```bash
python tools/launch_dsh.py --check
python tools/launch_dsh.py web --permission-mode read-only
python tools/launch_dsh.py headless --permission-mode read-only "Size a pump for 100 m³/h"
```

| mode | what starts |
|---|---|
| `web` | `dsh --profile web --patch ...`, the browser UI on loopback |
| `headless` | `dsh --profile headless --patch ... TASK`; a task of `-` reads stdin |
| `check` | the read-only probe, also reached with `--check` |

A real launch exports the skills to `.dsh/skills/`, writes the overlay to
`.dsh/patches/azoth-<mode>.yml`, pins the checkout as DSH's first workspace, and starts
DSH with `DSH_HOME` set to `<root>/.dsh-home` unless `--dsh-home` or the environment names
another. `--print-config` prints the overlay and `--dry-run` adds the exact argv; neither
writes, and neither exports the skills.

| flags | effect |
|---|---|
| `--persona engineer\|software` | the engineering experience (default) or the shipped coding preset |
| `--flowsheet F` | mount the flowsheet MCP server on `F`; defaults to `specs/flowsheets/demo.toml` |
| `--no-flowsheet` | do not mount a flowsheet server |
| `--palette P`, `--no-run` | passed to `azoth mcp`; the palette defaults to `specs/unit_ops` |
| `--study hazop` | web only; enable Agent Teams, mount the four presets, make the chair the root |
| `--skills full\|hazop\|none` | export all 90 catalog skills, the curated HAZOP subset, or none |
| `--permission-mode read-only\|workspace-write` | required for a launch; no default |
| `--provider NAME` | the default route: `deepseek`, `openai`, `anthropic`, `kimi` or `minimax` |
| `--model ID` | the model id; defaults to the provider's declared default |
| `--base-url URL`, `--api`, `--api-key-env` | use an OpenAI-compatible gateway instead of the native provider routes |
| `--reasoning-effort` | `off`, `low`, `high` or `max`; hosted route only |
| `--port`, `--no-open`, `--host`, `--allow-remote` | the web UI's binding; a non-loopback host needs `--allow-remote` |
| `--session-id` | name a headless session |
| `--dsh`, `--python`, `--azoth-bin`, `--node`, `--dsh-home` | name the toolchain |
| `--no-npx` | refuse the `npx` fallback |
| `--json` | a check report as JSON, or headless output as JSON |
| `--verbose`, `--timeout` | print the argv and notes; the per-probe timeout in seconds |

## The workspace and the two experiences

DSH scans the skills and instruction files of the **session workspace**, not the
process's working directory. The launcher therefore writes the checkout into
`$DSH_HOME/storages/workspace.json` as the first workspace, adding a record when it is
absent and preserving every other workspace and session. The welcome UI also opens the
workspace titled `azoth`, so a saved DSH selection does not reopen the default workspace.
Without that record a session opens DSH's own
`~/Documents/deepseek-harness/default-workspace`, and neither `AGENTS.md` nor `.dsh/skills`
is discovered.

`--persona engineer` (the default) mounts `azoth-engineer` as the web root preset: the
engineering persona, `agent-instructions` for `AGENTS.md`, the skill catalog, file and
shell tools, ask-user and compaction. Headless composes no preset roster, so there the
same prompt is written to the deployment `system-prompt`, where the base's
`agent-instructions` and skill rows read the same workspace. Web also mounts the azoth
welcome card. `--persona software` leaves DSH's shipped coding persona in place.
`--study hazop` (web only) keeps precedence over both and mounts the four role presets
instead; the headless one-shot composes no preset roster and refuses it.

The first time the page opens, the welcome card gives a one-line instruction, three
example asks and a link to the user manual. The model menu below the composer chooses the
provider and model; three starter buttons fill the composer with a pump sizing, the demo
separator, and relief and fire questions. A missing model key is reported by DSH; the key
is saved on the **Settings → Models** page or exported as the selected provider's
environment variable.

## Providers

Every launch without `--base-url` mounts five routes, so the model selector in the DSH UI
can switch without a launcher change. The table is declared in `harness.toml` and rendered
into the overlay:

| `--provider` | Provider route | Model default | Key |
|---|---|---|---|
| `deepseek` (default) | `deepseek-official` | `deepseek-v4-flash` | `DEEPSEEK_API_KEY` |
| `openai` | OpenAI catalog | `gpt-5.5` | `OPENAI_API_KEY` |
| `anthropic` | Anthropic catalog | `claude-sonnet-5` | `ANTHROPIC_API_KEY` |
| `kimi` | Moonshot catalog | `kimi-k2.6` | `MOONSHOT_API_KEY` |
| `minimax` | MiniMax catalog | `MiniMax-M2.7` | `MINIMAX_API_KEY` |

`--provider` only sets the session's default; the selector can choose another route or
model. `--model` overrides the provider's default id. OpenAI speaks the Responses API
through the catalog; Anthropic, Kimi and MiniMax use their catalog protocols. The
`--base-url` route is the escape hatch for an OpenAI-compatible gateway, an enterprise
endpoint or a model the catalog does not list; it replaces the native routes for that
launch. No open-weight deployment is required. The selector offers the routes whose
credentials are available; `--check` names which provider keys are set.

The environment carries the same choices: `AZOTH_DSH` and `AZOTH_BIN` name the runtime and
the CLI, `AZOTH_PYTHON` names the interpreter, `DSH_HOME` or `AZOTH_DSH_HOME` sets the
harness's home, `DSH_PERMISSION_MODE` is the permission mode, and `PYTHONPATH` is extended
with `python/src` for every child. The selected provider's key is the one named in the
providers table above; `--api-key-env` overrides it, and the `--base-url` route uses
`AZOTH_DSH_API_KEY` by default.

Resolution order for the runtime is `--dsh`, `AZOTH_DSH`, `dsh` on `PATH`, the Python SDK's
bundled runtime, then `npx --yes @deepseek-ai/dsh@<pinned>` unless `--no-npx`. The `azoth`
CLI is `--azoth-bin`, `AZOTH_BIN`, `target/release`, `target/debug`, `PATH`, then
`cargo run -q -p azoth-cli --`; without one the flowsheet MCP row is omitted and the check
warns, unless `--require-flowsheet` makes that a failure.

## The check contract

`--check` writes nothing: children run with `-B` and `PYTHONDONTWRITEBYTECODE=1`, and
`DSH_HOME` is a temporary directory. It probes, in order:

| probe | what it proves |
|---|---|
| `repo` | the checkout has `skills.toml`, `python/src/azoth`, `agents/deepseek` and `Cargo.toml` |
| `python` | the interpreter imports azoth and prints its version |
| `dsh` | the runtime answers `--version` and is on the tested `0.2` line |
| `node` | present and at the tested floor, only when the `npx` path is used |
| `azoth` | the CLI answers `--version`, or will build on launch |
| `flowsheet` | `azoth check` accepts `F` against the palette |
| `mcp` | a stdio `initialize` request and tool listing, under the name `azoth` |
| `bridge` | `python -m azoth.harness version` prints JSON |
| `plugin` | `node --check` and `node --test` for the plugin and the welcome UI |
| `workspace` | the first workspace is the checkout; a missing store is a warning because a launch seeds it |
| `preset` | the `azoth-engineer` prompt and `harness.toml` row exist in engineer mode |
| `ui` | the welcome UI's `client.js` and `dsh.client` manifest exist in engineer web mode |
| `provider` | the selected provider route and model are declared |
| `providers` | which provider key variables are set, without reading their values |
| `skills` | the exported skills are present, current, not orphaned, and in the pinned workspace |
| `api-key` | the selected provider's key environment variable is set; its value is never read |

Each probe is `ok`, `warn` or `fail`; one line each, or `--json` for a report of the form
`{"schema":"azoth.launch-check/1","ok":true,"checks":[{"name":"repo","status":"ok","detail":"…"}]}`.
The exit status is `0` when no probe failed and `1` otherwise.

## The model's tool surface

The calculation plugin registers four tools. Three are thin calls to the bridge; the
fourth is the orientation the model reads when the user asks what azoth can do:

| tool | arguments | bridge command |
|---|---|---|
| `azoth_help` | none | none; returns the glossary and example questions |
| `azoth_catalogue` | `query`, `kind`, `limit`, `offset` | `catalogue` |
| `azoth_spec` | `id`, `full` | `spec` |
| `azoth_calc` | `id`, `inputs`, `keycard`, `backend` | `run` |

A dimensioned input is a number in the unit `azoth_spec` declares, or a `{value, unit}`
pair, which is converted to that unit. Vectors and matrices are lists; a `record_list` is
a list of objects with its declared fields; enums, strings and booleans have their JSON
kinds; `components` and the name-list kinds are arrays of names. An unknown key, a missing
required input, a wrong dimension and a non-finite number are each refused by name.
`keycard` is a path under the working directory. `backend` is `auto`, `python` or `rust`,
and `auto` selects the compiled kernel when it is loaded.

The flowsheet MCP server is the existing `azoth mcp --flowsheet F`, mounted through
`@deepseek-ai/dsh-mcp-client` as server `azoth`. Its 20 edit commands appear as
`mcp__azoth__*`, covering instances and connections, parameters, boundary feeds and
products, recycles, instruments and signals, positions and names. Its four resources are
`azoth://document`, `azoth://diagnostics`, `azoth://report` and `azoth://catalogue`; every
tool call also returns the whole updated document, so a read is the answer to the call
that changed it. The server holds one document in memory and never writes it.

## The bridge contract

`python -m azoth.harness` is the process boundary between DSH and the library:

```text
python -m azoth.harness catalogue [--query TEXT] [--kind calc|model] [--limit N] [--offset N]
python -m azoth.harness spec ID [--full]
python -m azoth.harness run ID --inputs-json JSON|- [--keycard PATH] [--backend auto|python|rust]
python -m azoth.harness version
```

It writes JSON on stdout and diagnostics on stderr, in one of three envelopes (contents
elided):

```json
{"schema":"azoth.harness/1","kind":"catalogue","total":398,"offset":0,"limit":100,"items":[…]}
{"schema":"azoth.harness/1","kind":"result","id":"hydraulics.reynolds_number",
 "backend":"rust","result":{"re":…,"provenance":{…}}}
{"schema":"azoth.harness/1","kind":"error",
 "error":{"type":"UndefinedInput","field":"rho","message":"…"}}
```

A result is the library's `to_dict()`, so the provenance block, the verification status
and any skipped checks travel with the number. The exit status is `0` for success, `2` for
an unknown id or a usage error, `3` for an invalid input or one above 1 MB, `4` for an
`AzothError` raised by the calculation, and `5` for an internal failure or an output above
8 MB. The catalogue pages at most 500 rows.

The plugin imports no `@deepseek-ai/*` package: the DSH tool registry accepts a plain tool
definition, so an absolute-path mount needs no `node_modules`. The engineering logic stays
in Python, where it is typed and tested with the library; `plugin/bridge.js` is pure Node
and is tested with `node --test`.

## Configuration the launcher renders

| overlay row | what it configures |
|---|---|
| `azoth-calc` | the plugin, mounted by absolute path with the Python path and caps |
| `azoth-ui` | the plain-JS welcome card and starters; engineer web mode only |
| `mcp-azoth-flowsheet` | the flowsheet server; omitted by `--no-flowsheet` or a missing CLI |
| `llm-deepseek` | the hosted DeepSeek route: `DEEPSEEK_API_KEY` and the model ids |
| `llm-pi-ai` | OpenAI, Anthropic, Kimi and MiniMax catalog routes, or the `--base-url` gateway |
| `agent-default-model` | the provider and model every agent starts from |
| `agent-preset-registry` | the root preset; `azoth-engineer` in engineer mode |
| `preset-azoth-engineer` | the engineering persona, instructions, skills and tools |
| `agent-team` | the Team board, `maxTasks` from `harness.toml`, enabled by `--study hazop` |
| four preset rows | `azoth-hazop-chair`, `azoth-process`, `azoth-safety`, `azoth-scribe` |

The engineer preset and welcome UI are rendered only outside `--study hazop`; the team
and HAZOP preset rows are rendered only under it.

The values the generator reads are declared in
[`agents/deepseek/harness.toml`](../../../agents/deepseek/harness.toml): the tested DSH
release, the Node floor, the default model, the timeouts, the curated skill list and the
four preset ids. The web and headless profiles compose differently — web ships the preset
registry and disables the host's skill and subagent tools, headless does not — so the
launcher renders by mode rather than committing one patch.

## Skills and the team

The 90 catalog skills export with `name` and `description` frontmatter over their unchanged
bodies to the checkout's `.dsh/skills/`, which is the project root DSH scans once the
workspace is pinned; `--skills hazop` writes the curated subset named in `harness.toml`.
`agents/deepseek/skills/azoth-hazop.md` is a harness-only procedure, not a catalog skill,
and is what `/azoth-hazop` loads.

`--study hazop` (web profile) enables the Team board and mounts four presets:
`azoth-hazop-chair` as the root, and `azoth-process`, `azoth-safety` and `azoth-scribe` as
subagents. The chair creates a task per node × guideword and sequences the pipeline
`guideword → deviation → cause → consequence → safeguard`; the scribe renders the
worksheet. [Orchestration](./orchestration.md) states the formal composition; the
execution is a mapping of it, not a proof.

## Security and limits

A launch requires `--permission-mode read-only` or `workspace-write`; there is no default.
Read-only leaves calculations and the in-memory flowsheet edits available while refusing
file writes. The launcher sets `DSH_PERMISSION_MODE` from that choice and never mounts
`sdk-minimal`, whose `danger-full-access` pin is the wrong default. A non-loopback host
requires `--allow-remote`. The calculation tool accepts registry ids only — no `eval`, no
shell, no import by a model-supplied string; a keycard path must be under the working
directory. The bridge caps inputs at 1 MB; the plugin caps a result at 4 MiB and times a
call out at 120 s; the CLI caps its own output at 8 MB; the flowsheet MCP client times a
tool call at 60 s.

The library's models are `unverified` or `partially_verified`; a result is evidence for a
finding, not a design deliverable. The provenance block says which.
